# Tutorial Release Verification

DIMER Notebook Specification 3.0 requires clean-runtime execution evidence in addition to
static source conformance. This file is the per-run record for that gate; the procedure, the
static-check inventory and the recorded-execution table live in
[`../docs/release-verification.md`](../docs/release-verification.md). The two documents
describe the same status, and a change to one must be mirrored in the other.

## Revision model

A notebook release has three immutable source identities, all recorded by the notebook itself:

1. **Notebook blob** — `git rev-parse <commit>:tutorials/<notebook>`: the exact notebook bytes
   executed. The notebook is generated by `tools/build_notebook.py`; CI fails when the committed
   notebook differs from the generator's output (PAR3).
2. **Repository commit** — `metadata.dimer.generated_from.revision`, printed by the runtime cell as
   `NOTEBOOK_SOURCE.repository_revision`.
3. **Carried module digest** — `metadata.dimer.generated_from.module_sha256`, the SHA-256 of
   `src/lmpipeline/pipeline.py` as carried verbatim in Section 2.

The notebook is **standalone**: no repository checkout, no `lmpipeline` install, no credential.
The pinned base model (`HuggingFaceTB/SmolLM2-360M-Instruct` at the immutable revision carried by
the module) is public, so no Hugging Face token is needed. The runtime is a separate hash-locked
`uv` environment built by Section 1 (`tutorials/requirements-isolated.lock.txt`); nothing is
installed into the kernel, and a run that needs a kernel restart is **not** Run-all evidence
(RUN10/ENV6).

**Never place a token or any other secret in this record, notebook output, uploaded artifact,
screenshot or evidence note.**

## Required E2E verification procedure

Follow steps 1–5, 7–9 of the supported procedure in `../docs/release-verification.md`. In short:

1. Resolve the current `main` head, confirm exact-head CI is green, and record the notebook blob.
2. Open `language_model_finetuning_colab.ipynb` at that exact commit in a **fresh** Colab T4 (or
   Kaggle T4) runtime with no cached packages, model or source.
3. Leave every form field at its default and choose **Run all** once. Section 1 must build the
   isolated environment with no restart; record whether any restart or shim was needed (either one
   disqualifies the run).
4. Record Python, the isolated environment's torch / transformers / peft / bitsandbytes versions,
   GPU identity, the model revision, the dataset revision and digest, the splits, the base and
   adapted validation loss and perplexity, train loss, wall time and peak memory.
5. Confirm the reload check line: reloaded validation loss, its absolute difference from the
   in-memory loss against the 0.05-nat tolerance, and whether the 16-token greedy openings are
   identical. Record the numbers and the verdict; `NOT reproduced` is a finding, not a pass.
6. Re-run the Section 10 export cell once; the outputs must be re-created without error.
7. Optionally run one BYOD pass (`USE_BYOD = True`, `BYOD_PATH` or the upload) including one
   rejected input (REL12).
8. Section 11 (external-artifact section, default path): confirm it printed the pinned URL, SHA-256
   and producer of `sample-bundle-v1` before downloading, `artifact_source` = pinned sample artifact,
   the bundle's base model and revision equal to the pinned ones, `lora_b_max_abs`, the input manifest
   with the blank-prompt finding, `answers_differ`, verdict `not-measurable`, and the four files in
   `outputs/external_artifact/`. Confirm it never read this run's
   `outputs/language_model_finetuning_adapter_bundle.zip`.
9. Optionally, in a separate session, give the preserved ZIP to Section 11 as `Your own bundle ZIP`
   with its printed SHA-256 in `EXPECTED_ARTIFACT_ZIP_SHA256`.
